Формат: Self-Paced

## Мета

Навчитися створювати пари GPG ключів, підписувати файли цифровим підписом та верифікувати підписи за допомогою програми Kleopatra (Windows). Зрозуміти принцип роботи асиметричної криптографії.

---

## Середовище та інструментарій

| Інструмент | Призначення |
|---|---|
| **Kleopatra** | Графічний інтерфейс для управління GPG ключами |
| **Gpg4win** | Пакет що містить Kleopatra + GnuPG для Windows |
| **GnuPG (GPG)** | Ядро криптографії — реалізація OpenPGP стандарту |
| **Notepad** | Створення тестових документів |

**Відповідність Kleopatra та GPG командного рядка:**

| Kleopatra (GUI) | GPG термінал | Призначення |
|---|---|---|
| «New Key Pair» | `gpg --gen-key` | Створення ключів |
| «Sign» | `gpg --detach-sign` | Підпис файлу |
| «Verify» | `gpg --verify` | Верифікація підпису |
| «Export» | `gpg --export` | Експорт публічного ключа |
| «Import» | `gpg --import` | Імпорт чужого ключа |

## Підготовка — Встановлення Gpg4win

### Крок 0.1 — Завантажити Gpg4win

Відкрий браузер та перейди на:

```
https://www.gpg4win.org/download.html
```

Натисни **Download Gpg4win** → завантажиться інсталятор `gpg4win-X.X.X.exe`.

### Крок 0.2 — Встановити

Запусти інсталятор та вибери компоненти:
- ✅ **GnuPG** — обов'язково
- ✅ **Kleopatra** — обов'язково
- ✅ **GpgOL** — опціонально (інтеграція з Outlook)

Натисни **Next → Install → Finish**.

### Крок 0.3 — Запустити Kleopatra

Пуск → **Kleopatra** або знайди іконку на робочому столі.

---

## Фаза 1 — Створення пари ключів

### Крок 1.1 — Відкрити майстер створення ключів

У Kleopatra натисни:
```
Файл → Нова пара ключів
(File → New Key Pair)
```

Або кнопку **«New Key Pair»** на головному екрані.

### Крок 1.2 — Вибрати тип ключа

Вибери **«Create a personal OpenPGP key pair»**.

### Крок 1.3 — Заповнити дані

| Поле | Приклад |
|---|---|
| Name | Student25 |
| Email | student25@techfrontier.ua |
| Passphrase | придумай надійний пароль |

Натисни **Next → Create**.

### Крок 1.4 — Переглянути ключ

Після створення в головному вікні Kleopatra з'явиться твій ключ:

```
Student25 <student25@techfrontier.ua>
Fingerprint: A1B2 C3D4 E5F6 ... (40 символів)
```

Запиши свій **fingerprint:**

| Поле | Значення |
|---|---|
| Ім'я | |
| Email | |
| Fingerprint | |
| Дата створення | |

## Фаза 2 — Підписання файлу

### Крок 2.1 — Створити тестовий документ

Відкрий **Блокнот** (Notepad) та введи:

```
TechFrontier UA — Офіційний документ
Дата: 27.03.2024
Зміст: Договір з клієнтом №2024-042
Сума: 150 000 грн
Підписант: Дарія Кравець, IT-спеціаліст
```

Збережи як `C:\Users\[ім'я]\document.txt`

### Крок 2.2 — Підписати через Kleopatra

**Спосіб 1 — через меню Kleopatra:**
```
Файл → Підписати/Зашифрувати файли
(File → Sign/Encrypt Files)
```
→ Вибери `document.txt`
→ Постав галочку **«Sign»**
→ Вибери свій ключ
→ Натисни **Next → Sign**

**Спосіб 2 — через контекстне меню:**
1. Знайди `document.txt` в Провіднику
2. Правою кнопкою миші → **«Sign with Kleopatra»**
3. Вибери ключ → **Sign**

Введи **passphrase** коли з'явиться вікно.

Буде створено файл підпису `document.txt.sig` або `document.txt.asc`.

### Крок 2.3 — Переглянути файл підпису

Відкрий `document.txt.asc` в блокноті:

```
-----BEGIN PGP SIGNATURE-----

iHUEABYKAB0WIQTAJYf4HkSdSy7Geu...
...
-----END PGP SIGNATURE-----
```

## Фаза 3 — Верифікація підпису

### Крок 3.1 — Верифікувати через Kleopatra

```
Файл → Розшифрувати/Верифікувати
(File → Decrypt/Verify)
```
→ Вибери `document.txt.asc`
→ Kleopatra автоматично знайде `document.txt`

**Очікуваний результат:**
```
Good signature from "Student25 <student25@techfrontier.ua>"
   Signed: 27.03.2024
```

**Або через контекстне меню:**
1. Правою кнопкою на `document.txt.asc`
2. **«Verify with Kleopatra»**

### Крок 3.2 — Симулювати підробку документу

1. Відкрий `document.txt` в блокноті
2. Додай рядок: `ПІДРОБЛЕНО: сума змінена на 999 000 грн`
3. Збережи файл
4. Знову верифікуй підпис

**Очікуваний результат:**
```
 BAD signature — The signature is invalid
   The file may have been tampered with!
```

Запиши:

| Сценарій | Результат |
|---|---|
| Оригінальний файл | Good / Bad |
| Змінений файл | Good / Bad |

## Фаза 4 — Експорт та імпорт ключів

### Крок 4.1 — Експортувати свій публічний ключ

У Kleopatra:
1. Вибери свій ключ
2. **Файл → Експортувати** (File → Export)
3. Збережи як `student25_public.asc`

### Крок 4.2 — Імпортувати ключ іншого студента

1. Отримай файл публічного ключа від іншого студента
2. **Файл → Імпортувати** (File → Import)
3. Вибери файл `.asc`

Ключ з'явиться в списку Kleopatra з позначкою **«Not certified»** — це нормально для навчального середовища.

### Крок 4.3 — Верифікувати файл підписаний іншим студентом

1. Отримай підписаний файл від іншого студента
2. **Файл → Розшифрувати/Верифікувати**
3. Вибери `.sig` або `.asc` файл підпису

---

## Фаза 5 — Шифрування файлів

### Крок 5.1 — Зашифрувати файл

1. Правою кнопкою на файлі → **«Encrypt with Kleopatra»**
2. Вибери отримувача (свій ключ або ключ іншого студента)
3. Натисни **Next → Encrypt**

Створюється зашифрований файл `document.txt.gpg`.

### Крок 5.2 — Розшифрувати файл

1. Правою кнопкою на `document.txt.gpg`
2. **«Decrypt with Kleopatra»**
3. Введи passphrase

## Фаза 6 — Збереження результатів

Створи папку `C:\Users\[ім'я]\gpg_results\` та збережи:

| Файл | Вміст |
|---|---|
| `01_screenshot_key.png` | Скріншот свого ключа в Kleopatra |
| `02_document.txt` | Оригінальний підписаний документ |
| `03_document.txt.asc` | Файл підпису |
| `04_screenshot_good.png` | Скріншот Good signature |
| `05_screenshot_bad.png` | Скріншот BAD signature (змінений файл) |
| `06_student25_public.asc` | Експортований публічний ключ |
| `07_conclusion.txt` | Висновок |

### Написати висновок

Створи `07_conclusion.txt`:

```
ЛАБОРАТОРНА РОБОТА: Цифрові підписи GPG (Kleopatra)
=====================================================
Дата:      [сьогоднішня дата]
Студент:   [твоє ім'я]

1. Створено ключову пару:
   Fingerprint: [твій fingerprint]

2. Підписано файл: document.txt
   Підпис: document.txt.asc

3. Результати верифікації:
   - Оригінальний файл: Good signature 
   - Змінений файл:     BAD signature  

4. Висновок:
   Цифровий підпис гарантує цілісність документу.
   Будь-яка зміна після підписання робить підпис
   недійсним. Це унеможливлює підробку підписаних
   документів без виявлення.
```

## Ключові поняття

| Термін | Пояснення |
|---|---|
| **Приватний ключ** | Секретний — тільки у власника. Для підписання |
| **Публічний ключ** | Відкритий — можна поширювати. Для верифікації |
| **Fingerprint** | Унікальний хеш ключа для ідентифікації |
| **Passphrase** | Пароль що захищає приватний ключ |
| **Good signature** | Файл не змінювався після підписання |
| **BAD signature** | Файл змінено або підпис підроблено |
| **ASCII armor** | Текстове представлення бінарних даних (-----BEGIN PGP-----) |
